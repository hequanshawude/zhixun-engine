# 演示视频脚本（≤5 分钟）

按镜头切分，每段给出画面、旁白要点、对应证据文件。录屏时把终端字号调大（≥16pt）。

| # | 时长 | 画面 | 旁白要点 |
|---|---|---|---|
| 1 | 0:00–0:25 | 赛题页 + 三个数据集图标 | 赛题要的不是模型，是一套能持续改进模型的系统；评分对象是 A/B/C 三个 CPU 工业模型 |
| 2 | 0:25–1:00 | 终端：`python -m selftrain cpu --package ... --rounds 10` | 镜像内一条命令完成 10 轮；每轮从当前采纳的检查点继续，验证集更好才采纳 |
| 3 | 1:00–1:45 | 屏幕滚动账本 `rounds-ledger.jsonl` | 每轮都有"读历史-做实验-依据结果决策"：学习率、epoch、验证值、采纳/拒绝、理由 |
| 4 | 1:45–2:30 | 三条曲线叠加（基线 vs 我们的结果） | A +2.1%、B −5.6%、C −3.6%；三个都高于平台基线 |
| 5 | 2:30–3:10 | 对比表：固定表 / Qwen 调参 / Qwen 改代码 | 大模型能追平并反超人工调参；但让它改代码没有收益、贵 6 倍 |
| 6 | 3:10–3:45 | `widen_cpu_checkpoint.py` 输出 | Net2Net 加宽的前向漂移仅 0.06%–0.30%；A 加到 128 反而退化，说明不能盲目加容量 |
| 7 | 3:45–4:20 | `docker run --network none` 输出 | 断网、4 核 2G 下跑完 10 轮并输出 final-checkpoint.npz；大模型不可用自动降级 |
| 8 | 4:20–4:50 | SwanLab 页面 | 全部实验在云端可查，逐轮指标与决策都在 |
| 9 | 4:50–5:00 | 总结页 | 结论：高于基线、可复现、可回滚；局限：B 的误差仍在 600 量级 |

## 录制命令清单

```bash
# 1. 十轮续训（本地）
python -m selftrain cpu --package data/raw/cpu/a --out /tmp/demo-a --rounds 10 --driver llm

# 2. 断网容器
docker run --rm --network none --cpus=4 --memory=2g \
  -v "$PWD/data/raw/cpu/a:/data/package:ro" -v "$PWD/out/demo:/out" \
  zhixun-engine:preflight cpu --package /data/package --out /out --rounds 10 --driver llm

# 3. 加宽演示
python scripts/widen_cpu_checkpoint.py --profile C --checkpoint out/cpu-models/best/c.npz --hidden 128 --output /tmp/wide.npz

# 4. 单点评测
python scripts/eval_cpu_checkpoint.py "A:out/cpu-models/best/a.npz"
```

## 注意事项

- 不要在视频里出现 API Key、SwanLab 登录态、个人目录绝对路径；
- 若平台尚未开放，第 7 段用本地容器替代并口头说明；
- 时长控制在 4:50 以内，留出上传缓冲。
