# 智训引擎 v2 · 从官方检查点续训 A、B、C

## 运行与产物

先在仓库根目录构建基础镜像，再构建本方案。将官方包挂载到 /data，将空目录挂载到 /out。通过运行环境向容器注入 PYTRIO_API_KEY。镜像内没有密钥、公开数据副本或预计算的工业模型权重。

```sh
docker build -t zhixun-engine:preflight .
docker build -f Dockerfile.scheme-v2 -t zhixun-engine:scheme-v2-20261113 .
docker run --rm --cpus 4 --memory 2g -e PYTRIO_API_KEY -v /path/to/packages:/data:ro -v /path/to/output:/out zhixun-engine:scheme-v2-20261113
```

容器默认通过 PyTRiO 调用 Qwen/Qwen3.8-27B 的持久化 Sampler，为每轮选择学习率和训练时长。已有权重微调使用 3 个优化步骤、2704 个训练 token，两条留出决策均返回预期超参。训练记录见 [SwanLab](https://swanlab.cn/@hequan/zhixunyinqing/runs/18vv3qdh)。权重访问由赛事工作台配置。无云端连接时，逐轮账本会标明表策略回退。

每组从平台检查点出发，在 CPU 上续训 10 轮，先以公开验证集选择基础检查点，再以公开训练样本拟合一次修正。A 对乙醇与乙醛的易混样本进行多组传感器通道复核。B 将续训输出与树模型等权融合。C 用带传感器微扰的训练样本拟合寿命残差，融合系数 0.65。修正仅在该组公开验证指标改善时采纳。

每个输出子目录内的 final-checkpoint.npz 是基础检查点，predictor/ 是可独立复制的最终预测程序与权重。使用完整目录以保留选定的修正。每行输入为官方格式的 JSON 对象，必需字段为 inputs，可选字段为 task。示例命令为 `python /path/to/output/a/predictor/predict_scheme.py < inputs.jsonl > predictions.jsonl`。每组的 summary.json 记录基础检查点指标，predictor/selection.json 记录实际启用的预测器指标。如果平台仅加载基础检查点，则只能复现基础模型的输出；完整预测入口须经平台验收。

## 本版 CPU 验收

断网、4 核、2 GiB，使用官方起点和固定表策略，A、B、C 各完成 10 轮。评估使用公开验证集，隐藏集成绩待平台评测。云端微调记录来自此前的独立实验。

| 任务 | 指标 | 续训检查点 | 启用修正后 |
|---|---|---:|---:|
| A 气体识别 | Macro-F1 ↑ | 0.727878 | 0.911696 |
| B 轴承寿命 | RMSE，分钟 ↓ | 624.421155 | 574.949762 |
| C 发动机寿命 | RMSE，循环 ↓ | 51.492408 | 50.167304 |

复现断网验收时，在上面的 docker run 命令中使用 --network none，并在镜像标签之后添加 `cpu --packages-root /data --out /out --rounds 10 --widen auto --driver table`。公开验证集参与了方案筛选，因此结果可能高估新设备上的效果。
