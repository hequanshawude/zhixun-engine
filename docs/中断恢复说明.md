## 使用方式

首次运行时选择一个新的检查点路径：

```powershell
.\.venv\Scripts\python.exe -m selftrain demo --config configs/local.yaml --policy rule --checkpoint out/recovery/state.bin --pred-dir out/recovery/preds
```

意外停止后，保持原始数据、代码、依赖及算法配置，使用相同参数加上 `--resume`：

```powershell
.\.venv\Scripts\python.exe -m selftrain demo --config configs/local.yaml --policy rule --checkpoint out/recovery/state.bin --pred-dir out/recovery/preds --resume
```

CSV 的 `run` 命令也支持这两个选项；需要保留完整的原始批次前缀，不能只提供剩余批次。独立训练集也会校验，变化后拒绝恢复。已存在的检查点不会被新的普通运行静默覆盖。

## 保存与校验

- 保存模型、历史训练数据、漂移检测器、策略记忆、预算、已完成批次和预测索引；不保存日志连接、模型客户端或 API Key。
- 恢复前校验代码、Python/依赖版本、任务、算法配置及检查点完整性；重放输入前缀时逐批核对数据哈希。
- 预测文件和索引采用临时文件写完后替换。若预测已写出但该批尚未提交检查点，恢复时只接受内容相同的重放；索引不会重复追加。
- 预测缺失、内容冲突、旧数据变动、检查点损坏或版本不兼容都会拒绝恢复。
- 恢复使用新的实验记录，通过 `resume.json` 关联上一条记录。新记录只新增恢复阶段的逐批日志，汇总包含检查点中的已完成历史；审计时需沿关联查看前序记录。

测试覆盖预测写出后中断、写入替换失败保留旧检查点、重复输出、文件冲突、配置变更、数据前缀变更、检查点损坏、凭据排除及探索策略状态恢复。云端故意中断的实验显示 CRASHED 属于预期结果。

## 当前边界

检查点包含模型和历史数据，只加载本程序生成的可信本地文件，不应接收陌生来源的检查点。当前不支持跨版本迁移，也不支持多个进程同时写同一检查点或预测目录。

恢复以最后完整提交的批次为准；中断发生前但尚未提交的工作可能重做，其耗时未必进入恢复账本。检查点序列化与落盘开销尚未完整纳入成本统计，不能据此保证整场预算硬上限。当前也不提供操作系统断电后的完整事务保证。

LLM 模式暂不开放恢复，以免重放产生重复调用或无法核对费用。正式平台的批次确认、提交去重和恢复握手仍需 SDK 接入；本地文件幂等不等于平台提交恰好一次。
