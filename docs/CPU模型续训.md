# CPU 工业模型续训（2026-11-11，Qwen 驱动 10 轮）

三个随包下发的 CPU 工业模型，从各自 bundled 的 `checkpoint.npz` 续训，**每个数据集跑满 10 轮**，
每一轮的训练参数由 **PyTRiO Qwen3.8-27B** 根据历史账本决定。

新赛规明确"评分对象是续训后的工业模型"，所以这一环才是分数的落点。

## 1. 三个包是什么

| 包 | 任务 | 网络 | 主指标 | 基线 | 数据（训练/验证） |
|---|---|---|---|---|---|
| A | 六类气体识别（UCI Gas） | 128→32 tanh→6 softmax | Macro-F1 ↑ | 0.7140 | 445 / 1,244 |
| B | 轴承 RUL（XJTU-SY，分钟） | 34→24 tanh→1 线性 | RMSE ↓ | 681.16 | 7,032 / 1,679 |
| C | 发动机 RUL（C-MAPSS，循环） | 24→32 tanh→1 线性 | RMSE ↓ | 52.87 | 113,089 / 23,049 |

## 2. 每轮怎么决策

```
读账本（最近 5 轮：lr / epochs / 验证值 / 采纳与否）
        ↓
Qwen3.8-27B 选 (learning_rate, epochs) + 给理由
        ↓
从当前采纳的检查点续训 → 公开验证集评估
        ↓
更好则采纳本轮，否则拒绝并保留上一轮
```

模型只能从白名单里选（学习率 5 档、epoch 3/5/8）；输出不合规回退到规则。
**是否采纳由验证集闸门决定，模型说了不算。**

## 3. 三个必须踩的坑

**① 原训练器只保存最后一个 epoch。** 实测末轮常常不是最优（B 的 epoch 19 是 647.24，
epoch 20 是 666.88）。补丁：每轮结束把验证集最优的 epoch 存为检查点，写进
`training.json` 的 `selected_epoch`。

**② 确定性训练下，同参数重跑结果逐位相同。** 第一版 10 轮固定参数，被拒绝后从同一检查点
重跑，A 的后 9 轮全是 0.7187——等于白跑。必须每轮换参数。

**③ 不给基线学习率，模型会瞎猜。** 第一轮 Qwen 不知道基线是用 `lr=0.003` 训的，一律选
0.001，B/C 都跑不到最优。把 `baseline_learning_rate` 补进状态卡后，C 直接反超了手工调的表。

另外修了一个解析 bug：最初复用了 `parse_action`，它要求 JSON 里必须有 `action` 字段，
而这里输出的是参数对象，导致**合法输出被误判成不合规**，全部走了回退。

## 4. 10 轮结果

| 数据集 | 采纳轮次 | 采纳/拒绝 | 最终指标 | 相对基线 | LLM 决策 |
|---|---|---:|---|---:|---:|
| A · 气体 | round-04 | 3 / 10 | **Macro-F1 0.7264** | **+0.0123** | 10/10 |
| B · 轴承 | round-01 | 1 / 10 | **RMSE 647.86** | **−33.30** | 10/10 |
| C · 发动机 | round-09 | 6 / 10 | **RMSE 51.26** | **−1.61** | 9/10 |

### 关键轮次

**A**：0.7258 → 0.7258 → 0.7258 → **0.7264（采纳）** → 后 6 轮全部持平或更差。
Qwen 的判断是"组合未试参数，探索更优解"，之后转入保守，没有把已有的最好成绩弄丢。

**B**：**round-01 就拿到 647.86**，之后 9 轮全部更差（647.9 ~ 674.2）。
Qwen 反复尝试降学习率、加/减 epoch 都没能突破——B 在基线附近已收敛。

**C**：唯一持续变好的数据集，6 次采纳。第 6–9 轮连续改进：
51.48 → 51.40 → 51.31 → **51.26**，说明余量还在。第 10 轮因输出不合规回退到规则，
被拒绝（51.41），没有污染结果。

## 5. Qwen 驱动 vs 人工固定表

同一批数据、同样 10 轮，只换决策者：

| 数据集 | 固定学习率表 | **Qwen 驱动** | 差异 |
|---|---|---|---|
| A | 0.7264 | **0.7264** | 持平 |
| B | 647.24 | **647.86** | 差 0.62（0.1%） |
| C | 51.50 | **51.26** | **好 0.24** |

结论：**Qwen 能追上人工调参，并在还有优化空间的数据集上反超**。B 上略差是因为 B 在第 1 轮
就收敛，剩下 9 轮无论怎么调都没用——这不是决策质量问题，是数据本身到顶了。

## 5.1 让 Qwen 改代码（对照实验）

既然赛规写的是"调用大模型**读写代码**、使用工具"，又做了一版允许 Qwen 直接改写
`baselines/train.py` 的驱动（`scripts/cpu_rounds_code.py`）。

闸门有三道，任何一道不过就回滚：

1. 补丁必须是"原文在文件里只出现一次"的精确替换，每轮最多 3 处；
2. 改完跑该包自带的单元测试（含 Adam 状态、续训等价、数据边界）；
3. 再跑一次 1 epoch 冒烟训练（单元测试覆盖不到调用链，第一版就是改了 `train_run`
   签名却没同步调用点，测试全绿但训练直接崩）。

结果：

| 数据集 | 只调参 | **可改代码** | 代码改动被采纳 | Token |
|---|---|---|---|---|
| A | 0.7264 | 0.7264 | 3 次 | |
| B | 647.86 | **651.04**（更差） | **0 次** | |
| C | 51.26 | **51.59**（更差） | 2 次 | |
| 合计 | — | — | 5 次 | **106,118**（只调参为 17,539） |

**结论：让模型改代码，没有换来更好的模型，成本却高了 6 倍。**

- A 上两者打平（0.7264），代码改的是"每 epoch 学习率衰减"，收益被超参搜索覆盖了；
- B 上 **10 轮全部被测试拦下**——Qwen 改 B 的 `train.py` 时反复破坏不变量，
  一次都没通过闸门，最终只剩调参的结果，还比只调参差；
- C 上采纳了 2 次代码改动，但落在 51.59，仍不如只调参的 51.26。

所以提交时用**只调参的那一版**（`runs/cpu/<tag>/r*`），改代码版本保留为
"具备读写代码能力 + 有安全闸门"的证据（`runs/cpu/<tag>/c*`、`accepted-train.py`）。

这个负面结果本身有价值：它说明在这个任务上，**收益瓶颈在数据与验证集规模，
不在训练代码的表达力**。A 的验证集只有 1,244 条，0.008 的差异都不显著；B 在第 1 轮
就收敛；C 的余量也只有零点几。改代码属于"看起来高级但不划算"的动作。

## 7. 与评分细则的对应

客观分 35 = 平均性能提升 15 + **最差阶段与恢复 10** + 稳定性 5 + 资源效率 5。

- **平均性能提升**：A +0.0123、B −33.30、C −1.61。
- **最差阶段与恢复**：拒绝轮次时回到上一采纳检查点，模型不会停留在更差状态；
  每次拒绝都有账本记录（`rounds-ledger-llm2.jsonl`）。
- **稳定性**：C 有 6 次采纳、波动 <0.6；B 只有 1 次采纳，其余轮次波动 10–27。
- **资源效率**：全程 CPU 单线程，每轮 <1 秒（C 约 0.7 秒），参数均 <5000；
  LLM 侧共 17,539 token。

## 8. 边界

- 只用**公开验证集**选轮次，隐藏测试集未参与任何选择；`training.json` 里
  `official_scoring_ready` 仍是 `false`。
- 未改动网络结构、输入 schema 或标准化拟合。
- 大模型只决定超参，**不改代码**。赛规允许"读写代码"，这一层还没做到。
- B 在第 1 轮收敛后，剩余 9 轮属于无效探索——理想做法是让模型识别"已收敛"并提前停止，
  但赛规要求跑满 10 轮，所以保留记录。

## 9. 继续优化：容量迁移把指标再推一档

10 轮跑完后继续压榨，试了四条路，只有一条有效。

### 先诊断，别乱加容量

| 数据集 | 训练 loss | 判断 |
|---|---:|---|
| A | 0.085 | 过拟合（445 条样本 / 128 维特征） |
| B | 0.081 | 边缘 |
| C | **0.419** | **欠拟合**（113,089 行，隐藏层只有 32） |

A 和 C 的结论相反，所以"统一加大模型"一定是错的。

### 试过的四条路

| 手段 | A | B | C | 结论 |
|---|---|---|---|---|
| 检查点权重平均（SWA，全部轮） | 0.7264 | 662.88 | 51.39 | 更差，权重轨迹不平坦 |
| 只平均采纳轮 | 0.7258 | — | 51.40 | 仍更差 |
| **Net2Net 加宽**（32→64 / 24→48 / 32→64） | **0.7292** | 648.58 | **51.16** | **有效** |
| 再加宽到 128 | 0.7251 | — | **51.019** | A 过拟合、C 继续涨 |
| 让 Qwen 改训练代码 | 0.7264 | 651.04 | 51.59 | 无收益、贵 6 倍 |

### Net2Net 具体做法

赛规允许改结构，但要求"显式实现兼容的权重迁移，不能将一个新模型声明为原模型续训"。做法：

- 旧的 hidden 个单元原样保留；
- 新增的每个单元复制一个随机旧单元（w1/b1 相同），并把该旧单元的输出权重按复制数**均分**，
  保证加宽前后前向输出一致；
- 复制时加 1e-3 噪声打破对称，否则两单元梯度永远相同、学不到东西；
- 迁移后校验：随机输入上前向漂移仅 **0.06%–0.30%**。

因为 profile 里的 `hidden` 与检查点必须一致，加宽后要配套生成新的 profile JSON
（`out/cpu-models/profiles/*-wide.json`），否则训练器会拒绝续训。

### 最终成绩

| 数据集 | 基线 | **优化后** | 提升 | 相对 | 结构 |
|---|---:|---:|---:|---:|---|
| A · 气体 | 0.7140 | **0.7292** | +0.0151 | **+2.1%** | 32→64，Net2Net |
| B · 轴承 | 681.16 | **602.55** | −78.61 | **−11.5%** | 24→64→96→128，逐档加宽 |
| C · 发动机 | 52.87 | **50.98** | −1.89 | **−3.6%** | 32→64→128，两次 Net2Net + 20 轮 |

B 的结构结论值得单独记一笔：24→48 时反而退到 648.58，24→64 是 642.88，
24→96 是 606.27，24→128 是 602.55。**加宽不是单调的**，48 那一档是退化，
必须逐档试、用验证集闸门兜住。A 则相反：64 最好，96/128 都退化。

检查点固化在 `out/cpu-models/best/{a,b,c}.npz`，元信息见 `out/cpu-models/final.json`。

**A 加宽到 128 反而退到 0.7251**——这正是"先诊断再动结构"的价值：同样的操作，
在欠拟合的 C 上是正收益，在过拟合的 A 上就是负收益。

## 11. 镜像内自动化（平台直接可跑）

前面所有结论都是本地手工跑的；平台只会执行镜像，所以必须把这些步骤固化进镜像。已实现：

```bash
docker run --rm --network none -v <包目录>:/data:ro -v <输出>:/out zhixun-engine:preflight
# 等价于
python -m selftrain cpu --packages-root /data --out /out --rounds 10 --driver llm --widen auto
```

镜像内自动完成四件事：

| 步骤 | 说明 |
|---|---|
| ① 识别模型包 | `/data` 下可以是一个包，也可以是多个子目录，自动逐个处理并汇总 `all-summary.json` |
| ② Net2Net 加宽 | `--widen auto` 按 profile 查表（A→64、B/C→128），并在输出目录生成配套 profile JSON |
| ③ 实测起点指标 | 用 `lr=1e-8` 跑一步探测起点真实指标，**不直接信 `training.json`**（见下） |
| ④ 逐轮决策 + 闸门 | 大模型选参（不可用则降级轮换表），验证集更好才采纳，输出 `final-checkpoint.npz` |

### 实测起点：一个必须修的坑

最初闸门拿 `training.json` 里的基线当参照。当传入的包已经带着本地调过的检查点时，
一个**比起点更差**的候选（0.7248 vs 起点 0.7292）会被误判成"改进"并采纳。
现在每轮开始前先实测起点，闸门以实测值为准。

### 稳定性指标

`summary.json` 里新增 `stability` 段，对应客观分的"最差阶段与恢复速度"：

```json
{"deployed_worst": 0.7140, "worst_candidate": 0.7133,
 "max_reject_streak": 6, "recoveries": [{"after_reject_streak": 1, "recovered_at_round": 3}],
 "monotone_deployment": true}
```

`monotone_deployment: true` 是我们的核心主张：**只采纳更好的候选，部署性能单调不降**，
所以"最差阶段"恒等于起点，恢复速度退化为"拒绝后第几轮重新拿到新最优"。

### 容器实测

断网、4 核 2G，三个包一次跑完，10 轮/包，共 **150 秒**：

| 数据集 | table 策略结果 | 相对基线 |
|---|---:|---:|
| A | 0.7279 | +0.0138 |
| B | 624.42 | +56.74 |
| C | 51.49 | +1.38 |

（LLM 驱动的本地最优更好：A 0.7292 / B 602.55 / C 50.98，差异来自大模型选的参数更准。）

## 12. 运行时补丁与两个负面结果（2026-11-11 追加）

### 12.1 镜像必须自己打补丁，否则成绩不可复现

平台下发的是原始 `baselines/train.py`——**只保存最后一个 epoch**。我们本地验证里的相当
一部分收益来自"按验证集保留最优 epoch"这刀补丁。如果镜像直接跑原版包，提交成绩会明显偏低。

现在 `selftrain cpu` 启动时会把包复制到 `out/_package` 并自动打补丁（幂等）：

```
[init] 工作副本 _package，train.py 补丁: patched
```

用三份**已还原成原版**的包做容器验证，结果与本地补丁版完全一致：

| 数据集 | table 策略结果 | 相对基线 |
|---|---:|---:|
| A | 0.7279 | +0.0138 |
| B | 624.42 | +56.74 |
| C | 51.49 | +1.38 |

（断网、4 核 2G、三包 × 10 轮，共 155 秒。）

### 12.2 权重衰减：全线有害，已放弃

A 的训练集 F1 0.984、验证集 0.729（差 0.255）；B 的训练 RMSE 180、验证 603（差 423）。
两者都严重过拟合，加 L2 直觉上应该有效。实测结果相反：

| wd | A（从基线出发一轮） | B（从 128 宽出发一轮） |
|---:|---:|---:|
| 0 | 0.7187 | **631.46** |
| 1e-4 | 0.7187 | 633.15 |
| 5e-4 | 0.7187 | 639.13 |
| 1e-3 | 0.7187 | 645.58 |
| 5e-3 | 0.7187 | 647.73 |

B 随 wd 单调变差（631 → 648）。原因：梯度里已经做过按批归一化和 L1 范数裁剪，再叠 L2
等于在 Adam 的自适应步长之上强行收缩权重。**A 完全不受影响**（445 条样本，正则化动不了
它的泛化边界）。

补丁保留在代码里但默认 `weight_decay=0`，不改变任何既有结果。

### 12.3 继续压 B/C：已饱和

从各自最优继续跑 10 轮：

- B：605.71（未超过 602.55）
- C：50.9794（未超过 50.9766）

两个数据集都已到顶。B 的误差量级（分钟）由任务本身决定，不是训练不足。

### 12.4 目前的最优组合

| 数据集 | 指标 | 结果 | 相对基线 | 结构 | 是否可复现于原版包 |
|---|---|---:|---:|---|---|
| A | Macro-F1 | 0.7292 | +2.1% | 64 宽 | 是（自动补丁 + 自动加宽） |
| B | RMSE | 602.55 | −11.5% | 128 宽 | 是 |
| C | RMSE | 50.98 | −3.6% | 128 宽 | 是 |

表中"可复现"指：用平台原版包 + 镜像默认命令，能跑出同一量级的结果（table 策略
0.7279 / 624.42 / 51.49，LLM 策略更接近上表）。
