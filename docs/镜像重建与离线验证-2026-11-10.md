## 3. 本次代码变更

两处，均不改变默认行为：

1. **`model.finetune_recency`（新增，默认 `row`）**
   `finetune` 动作原先按"拼接后行序"做新旧衰减。行序只有在"追加写入的单一时间序列"里
   才等于时间序；C-MAPSS 这类按设备分组排列的 CSV 里，行序与时间无关，会让排在文件末尾的
   设备被无端加权。
   新增 `batch` 模式：按**批次到达顺序**衰减（`finetune_decay` / `finetune_floor` 可调）。
   默认仍是 `row`，因此既有结论与数字全部保持不变。

2. **删除 `loop.py` 中未使用的 `rolled_back` 局部变量**（纯清理）。

变更后 `pyflakes selftrain` 无告警。

## 4. 断网离线验证

命令（镜像内不联网，只挂载只读数据与可写输出）：

```powershell
docker run --rm --network none --cpus=4 --memory=2g `
  -v "$PWD\data\processed:/data:ro" -v "$PWD\out\docker-offline:/out" `
  zhixun-engine:preflight run `
    --data-dir /data/cmapss-fd001/stream `
    --train-csv /data/cmapss-fd001-holdout/train.csv `
    --gate-csv /data/cmapss-fd001-holdout/gate.csv `
    --target y --task regression --policy rule `
    --config /app/configs/cmapss-fd001-holdout-rule.yaml `
    --pred-dir /out/preds --quiet
```

结果：

| 项 | 宿主机 | 容器（断网） |
|---|---|---|
| 10 批批均 MAE | 26.5943 | **26.5943** |
| 静态基线 | 26.3993 | 26.3993 |
| 逐批耗时合计 | 17.5 s | 12.0 s（整容器 14.1 s） |
| 预测文件 | — | `/out/preds/pred_0000..0009.csv` + `index.json` |

- `--memory=2g` 通过，说明峰值内存明显低于 8 GB 限制。
- `--cpus=4` 下 10 批 14 秒完成，单批约 1.4 秒。
- 断网与联网结果完全一致，说明运行期不依赖外网（本配置 `harness.enabled: false`）。

## 5. 仍然存在的差距

1. **容器内日志会写进容器**：`configs/cmapss-fd001-holdout-*.yaml` 的 `log.out_dir` 是相对路径
   （`runs/...`），在容器里落到 `/app/runs`，`--rm` 后丢失。正式评测必须用
   `configs/offline.yaml`（`/out/runs`），或把所用配置的 `out_dir` 改成绝对路径。
   这一点尚未形成自动化校验。
2. **未验证官方入口**：官方 SDK、公开集划分、静态基线、评测脚本、资源时限、记录规范字段
   都还没有，镜像只能按本地约定跑。
3. **`harness.enabled: true` 的断网行为未验证**：正式离线环境里 PyTRiO 是否可达仍待赛方说明。
   当前断网验证跑的是规则策略，不涉及模型服务。
4. **镜像未重新测"27B 决策"路径**：本轮没有消耗 PyTRiO 额度，27B 相关结论仍引用
   《Qwen27B 真实数据对照》里旧镜像的结果；如要复核需重新联网运行。
