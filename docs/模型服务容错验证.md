# 模型服务容错验证（2026-11-09）

本轮修复了决策解析与异常调用记账，57 项自动检查全部通过；本机与断网容器各通过 6 项模拟 HTTP 接口检查。实际平台模型服务仍未接入，默认不启用 LLM。

## 修复内容

- 原解析方式在第一个右花括号处截断，提示词要求的 `params: {}` 也会导致完整回复解析失败。现在解析完整 JSON 对象，支持嵌套对象、代码框、前导说明及字符串内的括号和转义字符；截断回复、数组或多个连续决策对象会被拒绝。
- 只接受允许列表中的动作。当前执行器未实现外部自定义参数，因此拒绝非空或类型错误的参数，不再静默忽略。缓存只保存规范化的合法决策，命中缓存仍检查当前动作限制。
- LLM 失败后采用固定规则；探索策略仅在显式选择 `bandit` 时使用。连续三次失败后停止调用服务，降级原因写入逐批记录。
- 收到响应后先保存服务返回的 Token 用量，再检查内容。响应结构错误不重复请求；认证等不可重试的 HTTP 错误不反复调用。
- 网络失败、响应缺少用量等情况计入 `unknown_llm_usage_calls`，不把“无法确认用量”解释为“免费”。后续成功重试不会抹掉之前的未知记录。
- 重试共用同一个请求时间窗口，预算耗尽时跳过新请求；没有可执行更新时也不会调用服务。当前缓存命中不消耗额外 Token。

## 仍需官方接口确认

这些检查验证本地兼容接口实现，不证明 PyTRiO 的认证、模型 ID、响应协议或计费已接通。未知用量需由官方账单或查询接口补齐；现有 Token 检查仅能在已知额度耗尽后阻止请求，尚不能保证单次请求不超出额度。

重试共享时间窗口，但底层网络读取仍采用 socket 超时，不是对整次调用的独立进程强制限时。平台若要求严格的整批时限，仍需统一监管预测、检测、模型服务、训练和日志等阶段。

复现本地接口检查：

```powershell
.\.venv\Scripts\python.exe scripts\harness_check.py
```
